# Names and marks

The Apache License 2.0 that covers this software grants **no rights in the
project's names, logos or marks** (section 6). This file says where the terms
that do govern them live.

## There is one marks policy, and it is not this file

`sayfirst` is the project's name, not this repository's. The same name covers
the open control plane, this client, and the packages and command both publish,
so one document states the terms for all of them: **`TRADEMARKS.md` in the open
control plane repository**, which the constitution names as the document
governing mark use (article 15).

It is not repeated here, for the reason article 0 gives when it forbids copying
the constitution into another open repository: *a copy drifts*. A second marks
policy would be a second answer to a question one document already answers, and
it would be the wrong answer from the first amendment onward — silently, because
nothing makes two prose documents disagree out loud.

## Where that repository is

<https://github.com/fredaime/sayfirst-control-plane>, and the text that governs
is its
[`TRADEMARKS.md`](https://github.com/fredaime/sayfirst-control-plane/blob/main/TRADEMARKS.md).

**That URL was written in the act that created this public repository, and not
before.** The open control plane is published as a repository created fresh
(constitution article 0; the reasoning is in the control plane's `SECURITY.md`),
so until that repository existed a link here could only have named the one
repository this project has decided never to make public — a link resolving for
nobody, in the file a reader consults precisely because they are outside the
project. `tests/test_pointers_survive_publication.py` refuses any reader-facing
link to that repository, and it is what kept this paragraph from being written
early.

A question about using the name goes to the lead, at
**frederic.aime@gmail.com**.

## What the terms say, in one line

They are the ordinary permissive-project terms: say truthfully that your
software uses or is compatible with `sayfirst`, redistribute unmodified releases
under the project's name, and refer to the project by name freely — but do not
name your own product, package or organisation after it, do not imply
endorsement, and give a modified version a different name and say what it is
based on. **That line is a summary and governs nothing**; the control plane's
`TRADEMARKS.md` is the text.
